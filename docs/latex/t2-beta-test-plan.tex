\section{Scope}
%=============================================================================

\textbf{Beta objective.} Two boards accept a ``start SEB'' command from the server, and SEB launches on both.

Repository: \url{https://github.com/cannon-spencer/riscv-exam-computer}. Commit tested: \texttt{027d47894359fdc4bdf7c9e229fe81d56dff1a36}

\paragraph{In scope.} Control server, board agent, start and stop scripts and sudoers rule, the install scripts, the SEB kiosk session on the board, and the lockdown and performance items carried over from alpha.

\paragraph{Out of scope.} Canvas exam completion; kernel and boot-chain hardening (including \path{scripts/verity}); an instructor web interface (\path{exam-env/frontend} is empty, so the instructor uses \texttt{curl}); server-pushed exam configuration; and the separate GPU/cage build, which lives on one isolated board and is not in the repository.

\paragraph{Notation.} A value marked \prop\ is a proposed target chosen by the team, not derived from the code or a stakeholder requirement. The first full test run records a baseline, and the team then confirms or revises each such value.

\subsection{How alpha testing changed the project}

\begin{itemize}\setlength{\itemsep}{0.12em}
  \item \textbf{On-board SEB builds were unreliable} (log 2026-09-23). SEB is now built once on a board and installed from a riscv64 release binary.
  \item \textbf{Campus networks block inbound connections.} The control server moved from an Oracle Cloud VM, which ran out of memory on package installs, to a laptop behind a Cloudflare tunnel, so boards only make outbound HTTPS requests (log 2026-09-23). Eduroam also blocks SSH to the board, so boards are registered as UF devices and reached over Tailscale.
  \item \textbf{Canvas is very slow on the board.} Clicks take 10\,s or more and the page paints in tiles (log 2026-09-30). A separate investigation on an isolated board found the SEB web process at 100\% of one core and a post-login load of over two minutes in a single timed run. That work is not in the repository.
  \item \textbf{Thermals and display glitches.} Two sessions of about 12 hours ran without a crash, but the board reached about 75\,\textdegree{}C with no heatsink or fan, and the display glitched several times (log 2026-09-30).
  \item \textbf{A failed UF login leaves the user stuck} on \texttt{ufl.edu} under SEB's navigation lockdown (log 2026-09-30). It is recorded as BUG-03 in the M4 report and has no beta test.
  \item \textbf{Control grew from a heartbeat to a job queue.} The server now keeps an inventory and one pending job per board, and the agent starts and stops SEB through sudo-whitelisted scripts (log 2026-09-30).
\end{itemize}

\subsection{How alpha testing shaped this plan}

\begin{itemize}\setlength{\itemsep}{0.12em}
  \item Release-binary install path: INS-01.
  \item Network and control path: SRV-01 to SRV-09, AGT-02 to AGT-05, SEC-02, SEC-03.
  \item Canvas speed: PERF-01, PERF-02.
  \item Thermals and glitches: PERF-03, PERF-04.
  \item Lockdown was not tested in alpha: LD-01.
  \item Job queue: SRV, AGT, SES and DEMO tests, and EDGE-01.
  \item The server identifies boards by hostname, so two boards flashed from one image can collide: AGT-01.
  \item Failed-login trap: no beta test; tracked as BUG-03.
\end{itemize}

\subsection{Control server}

The server (\path{exam-env/server/src/main.rs}) listens on port 8000 and holds, per host name, the last heartbeat time, the last reported state and at most one pending job (\texttt{start} or \texttt{stop}).

\begin{table}[H]
  \centering
  \footnotesize
  \begin{tabularx}{\textwidth}{@{}l X@{}}
    \toprule
    \textbf{Route} & \textbf{Expected behavior} \\
    \midrule
    \texttt{POST /heartbeat} &
    Body \texttt{\{"host":\ldots,"state":\ldots\}}. Records the host, time and state. Replies \texttt{\{"ok":true,"job":\ldots\}} where \texttt{job} is \texttt{"start"}, \texttt{"stop"} or \texttt{null}. Missing \texttt{host}: 422. Invalid JSON: 400. No JSON content type: 415. \\
    \texttt{GET /machines} &
    Lists every host seen since the server started, with \texttt{state}, \texttt{pending} and \texttt{seen\_secs\_ago}, sorted by host. \\
    \texttt{POST /start} &
    Sets pending \texttt{start} on every host whose last heartbeat is 15\,s old or less, and returns the sorted list \texttt{queued}. Returns \texttt{"queued":[]} when no host is online. \\
    \texttt{POST /stop} &
    Same as \texttt{/start} with job \texttt{stop}. \\
    \bottomrule
  \end{tabularx}
  \caption{Server routes.}
  \label{tab:routes}
\end{table}

Job delivery rules (checked by SRV-01 to SRV-09):
\begin{itemize}\setlength{\itemsep}{0.12em}
  \item A job is handed out in the reply to the board's next heartbeat and then cleared.
  \item A pending \texttt{start} is not delivered while the board reports \texttt{running}; it stays pending and is delivered the first time the board reports another state.
  \item A pending \texttt{stop} is delivered regardless of reported state.
  \item There is one pending slot per board, so a later command replaces an earlier undelivered one.
  \item Inventory is held in memory only.
\end{itemize}

\begin{itemize}\setlength{\itemsep}{0.12em}
  \item The agent sleeps 5\,s after each POST, so the observed period is 5\,s plus the request. It reports \texttt{running} while the \texttt{sudo}/\texttt{xinit} child from \texttt{start-seb.sh} is alive, otherwise \texttt{idle}.
  \item The reported host name is the \texttt{HOSTNAME} environment variable, set by the systemd unit from the \texttt{\%H} specifier.
  \item The control URL is compiled into the agent: \path{https://riscv-exam-computer.download/heartbeat}.
  \item The agent opens no listening port.
  \item Sudo for the agent is limited to \path{/home/orangepi/start-seb.sh} and \path{/home/orangepi/stop-seb.sh}.
\end{itemize}

\subsection{Board session}

\paragraph{Start.} \texttt{start-seb.sh} runs as root and execs \texttt{xinit} on display \texttt{:1}, virtual terminal 3, starting \texttt{openbox} and then \path{/home/orangepi/safe-exam-browser --windowed} with a local start file (paths hardcoded for the \texttt{orangepi} account).

\paragraph{Stop.} \texttt{stop-seb.sh} kills the SEB and \texttt{xinit} processes and X1 socket holders, rebinds the framebuffer console, restores keyboard mode and switches to virtual terminal 1.

\subsection{Not implemented in the tested commit}

\begin{itemize}\setlength{\itemsep}{0.12em}
  \item The server code has no authentication on any route.
  \item \texttt{/start} and \texttt{/stop} address all online boards; there is no per-board targeting.
  \item The server does not distribute exam configuration; a later change is a pushed \texttt{.seb}.
  \item Secure start (the exam opening only under SEB): no mechanism exists yet; see SEC-01.
  \item Paths and the account name are hardcoded (\texttt{orangepi}); the install scripts do not install \texttt{openbox}, \texttt{xorg} or \texttt{xinit}; and the local start file is not in the repository.
\end{itemize}

\subsection{Equipment and conventions}

Two Orange Pi RV boards, each with an HDMI display, a USB keyboard, power and a UART adapter (115200 baud); a laptop running Docker and \texttt{cloudflared} with the \texttt{exam-server} tunnel; a network that reaches \path{https://riscv-exam-computer.download} (a lab network, or \texttt{ufdevice} with Tailscale for registered boards); and a stopwatch or screen recording. \subsection{Server (no hardware)}

Start a local server on \texttt{:8000} (\texttt{cargo run} in \path{exam-env/server}, or Docker without the tunnel). Do not use \path{./scripts/deploy-server.sh} or the public URL for these tests: that path is the live tunnel, and live boards would consume jobs. Drive SRV-01 to SRV-09 with \texttt{curl} to \texttt{http://127.0.0.1:8000}. SRV-09 needs a 16\,s wait after the last heartbeat.
